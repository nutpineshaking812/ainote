# 🎨 前端极简开发规范 (Frontend Standards)

本文档旨在通过统一的行为模式，确保平台 UI 的极简审美与逻辑的工程化。

---

## 1. 核心准则 (Golden Rules)

### 1.1 空间分配逻辑
*   **路由 (Route)**: 适用于**主战场**（列表管理、沉浸式编辑、复杂数据详情）。给用户完整的视觉呼吸空间。
*   **模态框 (Modal)**: 仅用于**极简子任务**（<=5个字段输入、二次确认、快捷设置）。严禁 Modal 嵌套。
*   **抽屉 (Drawer)**: 适用于**侧向配置或预览**，不破坏主页面上下文。

---

## 2. API 交互规范 (Data & API) —— **强制要求**

### 2.1 统一 API 客户端
*   **引用方式**: 必须使用 `import api from './index';`。
*   **处理机制**: 通过 `api` 实例进行统一的请求拦截、错误处理及数据封装。
*   **显式动作路径**: 对接后端的 Action 路由（如 `/get-list`, `/create`, `/delete`）。
*   **显式参数签名 (Mandatory)**: API 函数必须通过对象解构明确列出业务参数（如 `export const create = ({ name, desc }) => ...`）。严禁使用模糊的 `data` 或 `body` 变量。

### 2.2 唯一标识符：全面推进 `id`
*   **淘汰 `_id`**: 历史遗留的 `_id` 字段属于逐步淘汰对象。
*   **代码准则**: 在所有的 React 组件、Hook 及业务代码中，**一律优先引用 `item.id`**。后端迁移至 PostgreSQL 后已确认为 `id` 格式。

---

## 3. UI/UX 审美与国际化 (Standard)

### 3.1 零硬编码原则 (i18n)
*   **强制国际化**: 严禁在 JSX 中直接书写中文或英文。
*   **双向同步**: 所有的文本必须通过 `t('key')` 调用，并同步更新 `zh` 与 `en` 语言包。

### 3.2 品牌感与反馈
*   **空状态**: 必须使用 `<Empty />` 组件处理缺省数据。
*   **图标一致性**:
    *   数字员工: `RobotOutlined`
    *   知识集: `ReadOutlined`
    *   管理工具: `SettingOutlined`

---

## 4. 目录与逻辑 (Architecture)

*   **Logic 分离**: 复杂的转换逻辑应抽离到独立的 `hooks/` 或 `utils/`，保持 JSX 纯净。
*   **模块自治**: 页面私有组件放在页面目录下的 `components/`。
